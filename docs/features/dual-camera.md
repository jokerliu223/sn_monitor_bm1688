# feature：双路摄像头（正/反两面抓拍）

> 主 [README.md](../../README.md) 只写"怎么开双路"；本文件写**原理、配对机制与排障**。
> 相关：[uploader.md](uploader.md)（正反配对后怎么上传）、[../CHANGELOG.md](../CHANGELOG.md)（V2.1）。

## 用在哪、解决什么

一个工位**只放一块板**，但要同时拍到它的**正面（SN 贴纸面）和背面** ——
正面用来读 SN，背面用来留证（比如核对背面丝印/条码是否与正面 SN 是同一块板）。

装**两台摄像头**：相机1 对着正面（原来的那台，负责识别），相机2 对着背面（新加的，**只拍照不识别**）。
在相机1 识别命中的那一瞬间同步抓一帧背面图，正反两张一并上传，在产测网页端**成对展示**。

**这样一次放置就拿到两面证据，不用人工翻板重拍第二遍。**

## 两路是分开拉流，不合并

这是本版最容易误解的一点，明确写清：

| 问题 | 答案 |
|------|------|
| 两路 RTSP 是合并成一路吗？ | **不是**。`sn_monitor.py` 起**两个独立的 `FrameReader`**，各自一条 RTSP 连接、各自一个后台线程排空解码缓冲，互不干扰。 |
| 第二路也做 OCR 吗？ | **不做**。`reader2` 全程**只 `read()` 丢帧**，把缓冲排干净、留住最新帧，一次 OCR 都不跑。识别链路只有正面一路。 |
| 硬件吃得下吗？ | 吃得下。BM1688 有 2 个硬件视频解码核（`/proc/soph/vpuinfo` 的 `vdec_coreid 1/2`），两路 4K HEVC 各分一核；背面不跑 OCR，NPU 负载几乎不增加。 |
| 正反怎么配成一对？ | **不是靠两路时间同步**。是正面识别**命中的那一刻**去 `reader2.latest()` 取背面最新帧，然后**把正面的 ISO 时间戳直接复制给背面**。DB 里两行 `captured_at` 相同是**写出来的**，不是分别测出来的 —— 所以配对必然成功。 |
| 为什么在"识别起点"抓而不是"命中后"抓？ | 代码注释写明：识别起点抓，与正面 `frames[0]` 时间最接近；OCR 本身要耗时约 1s，等命中再抓，背面可能已经换板了。 |
| 万一背面拿不到帧？ | 跳过背面，只落正面，**绝不阻塞/影响正面识别落库**。 |

## 参数

给 `--rtsp` 之外再加一个 `--rtsp2`。**空/不加 = 单路**（行为完全等同 V2.0.x，现有小/大板零影响）。

| 参数 | 默认 | 说明 |
|------|------|------|
| `--rtsp2` | (空) | 第二路（背面）RTSP。空=不开第二路 |
| `--rtsp2-grab-wait` | 0.5 | 命中时从第二路取最新帧的最大阻塞秒（小值防拖慢主识别） |

**前置条件**：第二台相机要接到 eth1 那台路由器/交换机上，跟相机1 同网段（见 README 2.1）。
先用 `ping` + 端口探测确认板子能到它：

```bash
ping -c1 192.168.1.8                                    # 通不通
timeout 4 bash -c "cat < /dev/null > /dev/tcp/192.168.1.8/8554" && echo 8554可连
```

**生产（服务方式）**：**大板工位什么都不用改** —— `deploy/sn-monitor-big.service` 的 `ExecStart` 里已经写好了 `--rtsp2`。

**小板工位**（`sn-monitor.service` 是单路）才需要手动补：编辑该单元的 `ExecStart`，
末尾追加 `--rtsp2 rtsp://192.168.1.8:8554/live0`，然后 `daemon-reload` + `restart`。

当前板子上跑的就是这行（`sn-monitor-big.service`）：
```
ExecStart=/usr/bin/python3 /data/soph_SN/sn_monitor.py --rtsp rtsp://192.168.1.9:8554/live0 \
  --idle 0 --mi 5 --profile big --rtsp2 rtsp://192.168.1.8:8554/live0
```

**手动前台（调试，最直观）**：
```bash
sudo python3 sn_monitor.py --rtsp rtsp://192.168.1.9:8554/live0 \
  --idle 0 --profile big --rtsp2 rtsp://192.168.1.8:8554/live0
```

启动时应看到两行分辨率打印，第二行确认背面已接上：
```
  流: 3840x2160
  第二路(背面): 3840x2160
```

若第二路不通，会打印 `⚠ 第二路 ... 暂不可达, 本次降级为单路(仅正面), 背面抓拍跳过` 然后照常单路运行 ——
**这是刻意设计：不阻塞重试、直接降级**，等相机调通再重启服务即可。

> **注意**：第二路**不做**断线自愈（周期重连）。跑起来之后若背面相机掉线，本进程不会自动接回来，
> 需重启服务；重启时别忘了背面推流（铁律 1）。正面那一路的自愈机制不受影响。

## 落盘 / 配对 / 上传

| 端 | 结果 |
|----|------|
| 板子落盘（正面） | `sn_<SN>_<ts>.jpg` + `sn_<SN>_<ts>.json`，JSON 多一个 `"side":"front"` |
| 板子落盘（背面） | `sn_<SN>_<ts>_back.jpg` + `sn_<SN>_<ts>_back.json`，`"side":"back"`，其中 `sn`/`ts`/`score` **继承正面** |
| 上传 | `sn-uploader` 靠 glob `sn_*.jpg` **天然把两张都拾取**，POST 时各带 `side`；正反用同一 ISO 时刻上传 |
| `.57` DB | 两行（`side` 各为 front/back），`captured_at` 一致 |
| 前端 | 按 `(sn, captured_at)` 归组，**一张卡片并排显示正面/背面** |

> ⚠️ 第二路同样是**单客户端源**：停/重启服务会断开背面摄像头，需同时重启其推流（与铁律 1 一致）。

## `.57` 侧：升级已有部署必读

`.57` 的「SN 抓拍」页把上面的两行配成一张卡片。相关约定：

- `sn_captures` 表在 V2.1 新增了 `side` 列（`front`/`back`，默认 `front`）。
  **SQLAlchemy 的 `create_all` 只建表不做 ALTER**，老库不会自动多出这一列，
  接口会直接报 `no such column: sn_captures.side`。升级前必须手动补列：
  ```bash
  cp data/results.db data/results.db.bak_$(date +%Y%m%d_%H%M%S)
  sqlite3 data/results.db "ALTER TABLE sn_captures ADD COLUMN side VARCHAR(8) NOT NULL DEFAULT 'front';"
  ```
  老数据取默认值 `front`，正好等价于"老数据都是正面"，无需回填。
- 落盘文件名同步改了：`data/sn_captures/<SN>/<时间戳>_<side>.jpg`
  （带 `side` 后缀，否则同一命中正反同秒会互相覆盖）。
- 页面上时间显示的是**抓拍时间 `captured_at`**（缺失才回退入库时间 `uploaded_at`）；
  但**筛选框按入库时间 `uploaded_at` 过滤** —— 这是刻意的（入库时间永不为空、且不受板子时钟漂移影响），
  所以筛选出来的日期范围可能和卡片上显示的时间差一两天，属正常现象。
- **`.57` 端实现细节见该仓库自己的 `README.md`「SN 抓拍」章节**，不在本仓库维护。

## 排障

| 现象 | 排查 |
|------|------|
| 第二路没接上 | 启动日志有 `⚠ 第二路 ... 暂不可达, 本次降级为单路` = 正常降级。查：相机2 是否接在同一台路由器/交换机？`ping 192.168.1.8`？`ip route get 192.168.1.8` 是否回 `dev eth1`？端口 `8554` 可连？ |
| 背面图不变/是旧画面 | 相机2 推流是否真在动？背面靠 `reader2` 排空缓冲取最新帧，源停推就会一直是同一帧。另注意背面**无断线自愈**，掉线需重启服务 |
| 卡片只显示正面 | ① 上传是否带 `side`？（板子 `sn_results/*_back.json` 里应有 `"side":"back"`）② `.57` 库里那两行 `captured_at` 是否真的一致？（差一点点就配不上对）③ 老库是否忘了 `ALTER TABLE ... ADD COLUMN side`？ |
| 网页上时间与筛选日期差一两天 | 正常：卡片显示**抓拍时间**，筛选按**入库时间** |
